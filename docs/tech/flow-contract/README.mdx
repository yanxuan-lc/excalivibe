## 1. Two parties, three locations

This is the only one of the three plugins with state. Its artifacts do not stay in the plugin — they
install into a consuming project, and the requirements they act on live outside that project again.

| Location | Owned by | Tracked in git |
|---|---|---|
| `<project>/.flow/nodes/` · `.flow/genai/` (evaluators **and** the two record templates the e2e steps copy from) · `.flow/workflows/` · `.flow/config.yaml` | the plugin — copied in by `genai-init` | no: `genai-init` ignores all of `.flow/`, because it is an already-versioned artifact of the plugin it came from |
| `<project>/Makefile` (`genai-metrics`) · `<project>/tools/genai/thresholds.json` · `e2e.json` | **the project** | yes |
| `<project>_genai/backlogs/` · `archive/` — a **sibling** of the repository | the project owner | its own call; it has no history unless given one |

**The sibling directory's name is load-bearing.** A gate command receives no variables of any kind, so
it locates the requirements as `../$(basename "$PWD")_genai`. A different name breaks two gates, and it
breaks them silently.

## 2. The project's side of the contract

Five obligations, and only three of them are files the project writes:

| Obligation | Shape | Consequence if absent |
|---|---|---|
| a `genai-metrics` make target | prints one line beginning `genai-metrics: ` followed by one JSON object; **the exit code and all other output are ignored** | the `genai.implement` and `genai.merge` gates both return `metrics_missing` and say to hand it to a person |
| `tools/genai/thresholds.json` | coverage floors; `null` opts a dimension out, which is the only way out and is visible in the file. Also the `e2e` ceiling — and **an absent ceiling does not opt out**, the shipped `5` / `0.2` apply | `thresholds_missing` |
| `tools/genai/e2e.json` | `url` and `contains`: an endpoint of the app and a marker only its own response carries. `status` when it does not answer 200. **Due before the first acceptance run, not at install** — a fresh project has no port and nothing worth matching on | `config_missing` at `genai.e2e`'s entry, which consumes nothing — the step simply cannot start |
| an `openspec/` directory | `openspec/changes/` and `openspec/specs/` | `unreadable` from four atoms |
| the sibling `<project>_genai/` | one directory per requirement, state in its own frontmatter | `unreadable` from the backlog atoms |

The split is the point. **The project reports facts; the shipped definitions decide the verdict.** A
project that decides its own verdict has no gate, and a round that can edit the arithmetic is not being
measured by it — so the judgement lives in `.flow/genai/`, which is untracked and reinstalled from the
plugin. Only the floors belong to the project, in a file the round may not edit either.

## 3. The check interface

Every check any step makes is one atom behind one entry point:

```bash
node .flow/genai/check.mjs <atom> [--flag value]
```

**The path is relative to the project root, and that is a property of the engine, not a convention.** A
gate command runs in `checker.cwd ?? projectRoot`, so the same fixed path resolves identically no matter
where the caller stood.

The wire shape is one JSON document on stdout: `result` names the label, every other key is a fact
behind it. The gate reads the label through `label_from: result`, and **the whole object lands in the
event log**, which is what keeps a rejection reconstructible after the working tree has moved on.

Two rules govern the labels, both stated as rules in the plugin's `AGENTS.md`: a checker always exits 0
(a non-zero exit is reported by the engine as `failed` and the label is lost), and a rule's `on_result`
must cover exactly `values + [failed, unexecutable]`.

### The thirteen atoms

| Atom | Labels | Read by |
|---|---|---|
| `backlog-status --status <s>` | `present` · `absent` · `unreadable` | `genai.spec` entry · `genai.accept` gate · `genai.release` entry |
| `open-changes` | `present` · `absent` · `unreadable` | `genai.archive` entry · `genai.archive` gate · `genai.accept` entry |
| `spec-deltas` | `present` · `absent` · `unreadable` | `genai.implement` entry |
| `openspec-valid --scope <changes\|specs>` | `satisfied` · `validation_failed` · `totals_unreadable` · `openspec_unavailable` | `genai.spec` gate · `genai.archive` gate |
| `backlog-claimed` | `agreed` · `unclaimed` · `none_active` · `unreadable` | `genai.spec` gate |
| `worktree` | `clean` · `dirty` · `unreadable` | `genai.code-review` entry · `genai.merge` entry · `genai.archive` entry |
| `metrics` | `satisfied` · `tests_failing` · `no_tests` · `too_many_skipped` · `coverage_below_floor` · `metrics_missing` · `metrics_unreadable` · `thresholds_missing` | `genai.implement` gate · `genai.merge` gate |
| `spec-scenarios` | `unique` · `unnumbered` · `duplicated` · `count_mismatch` · `unreadable` | `genai.spec` gate |
| `e2e-manifest` | `accounted` · `unaccounted` · `over_ceiling` · `manifest_missing` · `manifest_malformed` · `unreadable` | `genai.e2e-author` gate |
| `e2e-mapping` | `matched` · `title_missing` · `file_missing` · `unreadable` | `genai.e2e-author` gate |
| `e2e-report` | `green` · `product_failure` · `test_failure` · `infra_failure` · `coverage_short` · `db_evidence_missing` · `report_missing` · `report_malformed` · `unreadable` | `genai.e2e` gate |
| `app-identity` | `identified` · `wrong_service` · `unreachable` · `config_missing` · `config_malformed` | `genai.e2e` entry |
| `signature-archive` | not a check — prints a sha256 | `genai.accept` output signature |
| `signature-e2e-suite` | not a check — prints a sha256 over the test files the manifests name | `genai.e2e-author` output signature |

**An atom reports a fact, never a verdict**, which is why one implementation serves two callers wanting
opposite answers: `open-changes` returning `absent` is a `pass` for the archive and a `ready` for the
acceptance, with no negation flag anywhere. Polarity lives in the caller's `on_result`.

`e2e-report` is the one atom whose labels choose between two **destinations** rather than two messages:
`product_failure` is a `reject` routed to `genai.implement`, `test_failure` a `delegate` routed to
`genai.e2e-author`. Edges route on the verdict alone — never on a report field or a gate label — so those
two buckets are the whole of what the graph can act on, and everything else the acceptance run gets wrong
is its own to fix.

Four atoms carry a timeout wherever they are called, because they spawn an external process:
`openspec-valid` and `spec-scenarios` allow 120 s (the second one asks openspec for a scenario count),
`e2e-report` 120 s, `app-identity` 30 s, and `metrics` 600 s — a full test suite with coverage.

`signature-e2e-suite` exists because the e2e tests have **no fixed location** — they go wherever the
project already keeps them — so no locator can reach them and the framework has nothing to hash. The
manifest names the files; the signature is taken over their contents. Without it, `genai.e2e-author`'s
no-spin rule could be satisfied by touching the manifest alone, which matters because the `delegate`
return edge into that step costs no patience.

`worktree` ignores untracked files, and that is load-bearing rather than incidental: the review step
leaves its records uncommitted on purpose, and the merge is what commits them. It is also what lets
`genai.code-review` carry a `clean-tree` entry rule at all — the rule cannot be falsified by the
records the step itself writes.

Three entry rules narrow their `when` rather than taking the `always` default, because their own step
falsifies them: `genai.spec` claims the backlog items it entered on (`first_attempt`, a root step),
and `genai.archive` folds away the changes and dirties the tree it entered on (`upstream_reran`, it
has an upstream that can re-run). Everything else is asked on every dispatch, which is what makes the
rules before an irreversible act worth relying on.

## 4. The ten steps

The roster and who runs each one. **The entry and gate rules are not reproduced here** — they are in
each `node.yaml` next to the comment explaining why they are shaped that way, and a copy in this tree
would rot the first time one changes.

| Step | Kind | Executor | Produces |
|---|---|---|---|
| `genai.spec` | produce | subagent `genai-spec-writer` | openspec changes and their spec deltas |
| `genai.spec-review` | judge | subagent `genai-spec-reviewer` | one `spec-review.md` per change |
| `genai.implement` | produce | subagent `genai-developer` | commits on the sprint branch |
| `genai.e2e-author` | produce | subagent `genai-e2e-author` | the e2e suite, and one `genai/e2e-manifest.md` per change |
| `genai.code-review` | judge | subagent `genai-code-reviewer` | one `review.md` per change |
| `genai.e2e` | verify | subagent `genai-e2e-runner` | one `genai/e2e-report.md` per change |
| `genai.merge` | effect | main | the merge commit |
| `genai.archive` | produce | main | the folded main specs |
| `genai.accept` | judge | subagent `genai-requirement-checker` | the archived requirements (an observed artifact, signed by command) |
| `genai.release` | effect | main | the changelog, and the only version bump of the round |

Three steps run on `main` rather than in a subagent, because all three need the whole round in view.
`.flow/workflows/genai-sprint.yaml` is the whitelist: a graph referencing anything outside it is refused
at creation.

## 5. What this flow relies on in its two external tools

Both are third-party, and in both cases the flow depends on a behaviour that is easy to get wrong:

**fsx.** A `brief.md` may interpolate exactly two slots, `{{report}}` and `{{state}}`, and neither of
these definitions uses either: the upstream artifacts, the artifact requirements and the rejection
message are printed unconditionally by the framework's own contract block, and no slot can name them.
A retired slot in a brief is a `fsx check` error, not a silent duplicate. Entry rules consume nothing
when they fail — no verdict, no patience, no attempt — which is what makes them safe to add. Gate commands receive **no** variables: not graph variables, not the
instance suffix, no injected environment. Every check therefore derives its context from `$PWD` or from
git, and that single fact explains both the fixed `.flow/genai/check.mjs` path and the load-bearing name
of the sibling directory.

**openspec.** Its exit code cannot be trusted: `validate` reports failures and still exits 0, and
`archive` carries warnings through and exits 0 as well. So `lib/openspec.mjs` reads the output and parses
the totals line, never the exit code — and a missing totals line is its own label (`totals_unreadable`)
rather than a pass, because nothing was actually validated. The rule that follows from this is in the
plugin's `AGENTS.md`: drive openspec's own commands, never reimplement its rules as local checks.

There is exactly one place that rule is bent, and it is bent knowingly. `openspec show --json` gives a
scenario's `rawText` and **drops its header**, so the scenario ids cannot be read from openspec's own
output — `lib/e2e.mjs` reads them from the markdown, matching openspec's reader as closely as it can
(any non-fenced level-4 header inside a requirement). What keeps that honest is asking openspec for the
scenario **count** and reporting a disagreement as `count_mismatch`, whose message says the definitions
are wrong rather than the spec. A second reader of someone else's format is a liability; a second reader
that checks itself against the first is a bounded one.

## 6. Version coupling

`.flow/nodes/` and `.flow/genai/` are **one unit**. An evaluator left at an older version than the
definition that calls it produces `unexecutable` or an unhandled label, so re-installing the definitions
means re-copying the evaluators in the same step.
