> 怎么操作一台计算机：让 agent 伸出自己的文本输出、在真实机器上动手的那批能力 —— 驱动浏览器、交给人一份能读的
> 文档、以及在终端够不到人的时候把人叫回来。
> **权威来源：`src/plugins/computer-use/`** —— 4 个 skill，外加本仓库唯一的一组 hooks。
> 版本 3.0.0。hooks 只有 Claude 端有；Codex 和 common 布局拿到那 4 个 skill。

## 你得到什么

| 能力 | 它解决的问题 |
|---|---|
| `graceful-browser` | 任务需要真实浏览器，而这台机器上到底有哪套自动化栈事先无法知道 |
| `mdx-artifact` | 产出是给人读的，而终端里一坨裸 markdown 不算 |
| `notify-user` | 活干完了、或者卡住了，而当时没人在看 |
| `install-computer-use` | 上面三个各有前置，而任何东西都不该在没问过的情况下装上 |
| hooks（仅 Claude） | 同一条通知，在回合结束时自动发出 —— **不开启则完全不动** |

这里没有任何东西是靠"computer use"这个词触发的。每个能力都触发于**它自己的场景**，所以无论是人在问、编排器在派发、
还是别的 skill 在委托，它们都一样工作。

## 安装与前置

```
/computer-use:install-computer-use
```

这条命令是设计好的入口，也是唯一一个你要**点名调用**的 skill。它会判断这台机器还缺什么，并在**得到你同意后**补上
—— 它绝不静默安装。

各能力实际需要什么：

| 能力 | 需要 | 缺了会怎样 |
|---|---|---|
| `graceful-browser` | 三者之一：会话自带的浏览器、Chrome DevTools MCP、Playwright | 顺着清单往下降级，并说明最后落在哪一档 |
| `mdx-artifact` | 全局 `mdxv` CLI | skill 会告诉你它不在，而不是写出一个没人能看的文件 |
| `notify-user` | **发送**不需要任何东西；**被打扰**需要你的同意 | 发送开箱可用；自动那一半保持关闭 |
| hooks | 插件装在 Claude 端，且跑过一次 `notify.sh --init` | 注册上了，但不出声 |

## graceful-browser

**在碰页面之前先定用哪套浏览器栈，并且透明降级。** 优先顺序是固定的，而且这个顺序有讲究：先用会话自带的浏览器
（它带着用户真实的 profile，所以任何需要登录的东西本来就已经能用），然后是 Chrome DevTools MCP，最后 Playwright
兜底。

只要任务会碰浏览器就用它 —— 打开页面、截图、填表单、走一遍流程、看一眼登录后面的东西、验证已部署的页面。**栈不由
你选**，这正是这个 skill 存在的意义。

随附 `scripts/start-chrome-devtools.sh`，服务中间那一档。

**最佳实践。** 说你想对页面做什么，不要说用哪个工具 —— 会话已经有浏览器时还点名 Playwright，等于把 profile 和登录
态一起扔掉。三档全失败时 skill 会停下来说明；那是一份报告，不是重试循环，所以要去回应它，而不是再问一遍。

## mdx-artifact

**把内容变成一份人真能读的文档**，然后用 `mdxv` 起一个本地主题化预览。当交付物是报告、提案、设计综述、看板或说明
时就用它 —— 包括对方只说了"弄得好看点"、完全没提 MDX 的情况。

它给你什么：Hero 抬头，`<Section>` / `<Callout>` / `<Fields>` 块，数据卡，卡片网格，五套配色（默认 `indigo`，另有
`teal`、`rose`、`amber`、`lime`），LaTeX 公式，以及两种图表围栏 —— ` ```dot ` 画依赖与分层图，` ```mermaid ` 画类图、
ER、状态机和时序图。

深度内容在 `references/blocks.md`（组件的确切语法）和 `references/example.mdx`（一份完整文档）里，只在需要时才加载。

**最佳实践。** 正文按普通 markdown 写，只在某一节、某段旁注或某块元数据**确实需要更多结构**时才上组件 —— 一份由
组件堆成的文档，比一份由散文写成的更难改。markdown 本身就是合法 MDX，所以把 `.md` 改名成 `.mdx` 就能原样迁移。另外
记住 GitHub 对 `.mdx` 只显示源码：如果读者是在 GitHub 上浏览，那是选 `.md` 的理由，不是跟渲染器较劲的理由。

## notify-user

**判断某个时刻是否值得把人的注意力拽回来，值得的话就在屏幕之外找到他。** 值得打扰的场景：长任务在没人看的时候
结束了、进展卡在只有他能给的答案上、有东西坏了而且不会自己好、或者他明确说过"完了叫我"。

**发送不需要任何设置；被打扰需要。** 这个不对称是刻意的，也是整个设计的重心 —— 模型发的通知是有人要求过的，而
hook 发的通知，是因为一个插件被装上了，而这台机器的主人从没同意过被打扰。所以手动那半立即可用，自动那半发出来
就是不动的。

### 配置

优先级从高到低：**环境变量**（`NOTIFY_USER_*`）、**YAML 文件**（`$NOTIFY_USER_CONFIG`，否则
`~/.config/excalivibe/notify-user.yaml`）、然后是默认值。

| 设置 | YAML 键 | 默认 |
|---|---|---|
| 总开关 | `enabled` | 开 |
| 渠道 | `channels` | `macos`（目前只发了这一个） |
| 声音 | `sound` | `Glass`；空或 `null` 表示静音 |
| 标题 | `title` | `Agent` |
| 回合结束阈值 | `min-seconds` | 60 |
| 回合结束时通知 | `on-turn-end` | **关** |
| 被阻塞时通知 | `on-blocked` | **关** |

两条命令：

```bash
notify.sh --init      # 写一份带注释的配置文件；绝不覆盖已存在的
notify.sh --doctor    # 当前配置、会不会发、以及一条真实的测试横幅
```

`--init` 是记录同意的地方 —— 它就是把自动那半打开的开关。`--doctor` 回答的是所有人真正会问的那个问题：
"我怎么什么都没看见"。

**它接受的 YAML 是一个很小的子集**：扁平映射，不支持嵌套、不支持 `- item` 序列、不支持锚点、不支持多行标量。POSIX
sh 里没有 YAML 解析器，而这个文件在每个回合结束时都要读，所以依赖 `yq` 或 Python 就意味着在没装它们的机器上整个功能
失效。**子集之外的任何东西都会带行号报出来，绝不跳过** —— 一个半懂的配置解析器比一个直接拒绝的更糟，因为被忽略的
一行看起来和"这个设置没起作用"完全一样，而沉默正是这个功能唯一的故障表现。

**最佳实践。** 加渠道请往 `scripts/channels/` 丢一个脚本，不要去改 `notify.sh`。`min-seconds` 要设得比"你愿意坐着
看完的回合长度"更高；把这个功能彻底弄丢的最快方式，就是让每个八秒的回合都弹一次横幅。

## Hooks（仅 Claude）

两个文件，`hooks/hooks.json` 和 `hooks/turn-notify.sh`，存在的理由只有一个：在终端够不到你的那两个时刻，
**不用被要求**就把 `notify-user` 的通知发出去。

| 事件 | 参数 | 超时 | 做什么 |
|---|---|---|---|
| `UserPromptSubmit` | `prompt-start` | 5 秒 | 给回合开始打时间戳。**什么都不发** |
| `Stop` | `turn-end` | 15 秒，async | 回合结束 —— **跑得比 `min-seconds` 久**才通知 |
| `Notification`（`permission_prompt`） | `blocked` | 15 秒，async | Claude 卡在一个权限决定上 |

### 为什么要打时间戳

`Stop` 知道回合结束了，**但完全不知道它跑了多久**。而耗时就是唯一的闸门，所以只能从另一头量 —— 于是有了一个
`UserPromptSubmit` hook，它唯一的职责就是写一个时间戳。状态放在 `$CLAUDE_PLUGIN_DATA`（否则 `$TMPDIR`）下的
`notify-user-turns`，一个会话一个文件，并且在进来时顺手清掉超过一天的旧戳，这样崩掉的回合不会让目录无限长大。

### 调它之前值得知道的两个行为

**所有输出走 stderr，stdout 上什么都不写。** `UserPromptSubmit` hook 的 stdout 会被当作额外指令注入模型上下文，
所以一个多余的 `echo` 不是外观 bug —— 那是模型会当成"你打过的字"来读的文本。脚本在第一行就 `1>&2` 重定向了。

**它降级，不猜。** 载荷是 JSON，用机器上现成的东西解析 —— 先 `jq`，否则 `node`。两个都没有时字段返回空，你会收到
一条更短的通知。这是刻意的：手写一个 `sed` 解析 `last_assistant_message`，在任何含引号的消息上都会静默返回错的
文本，而**错比没有更糟**。唯一看得见的代价是：没有 JSON 解析器就拿不到 session id，于是同一目录下的两个并发会话
会共用一个时间戳，其中一个报的是另一个的耗时 —— 差几分钟，但绝不会在"是否已完成"上出错。

**`blocked` 事件没有耗时闸门**，这是刻意的：一个被阻塞的回合，无论刚被阻塞多短，都没有在推进，而不知道这件事的
代价是整个会话原地空转。

### 怎么关掉

下面任何一条都能让它安静，从最窄到最宽：设 `on-turn-end: false`；设 `enabled: false` 会停掉所有渠道、包括手动那
半；或者卸掉插件。脚本在遇到第一个被关掉的开关时就 exit 0，所以一个关闭状态的 hook 每回合只花一次配置读取，别无
开销。

## 全插件层面的最佳实践

- **要结果，不要点工具。** "检查一下已部署的页面渲染是否正常"能正确路由；"用 Playwright 检查页面"会把两档更好的
  选择扔掉。
- **`install-computer-use` 一台机器跑一次，不是一个项目跑一次。** 它配置的是用户级的东西。
- **在认定通知有 bug 之前先 `--doctor`。** 十次里有九次是 `on-turn-end` 还没开，而那是出厂默认，不是故障。
- **给人看的文档是 `mdx-artifact` 的活，不是一墙终端文字。** 反过来同样成立：两行就能说完的答案不需要一份文档。
